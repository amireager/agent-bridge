# Agent Bridge — آینه‌ی زنده، مترجم و آزمایشگاه مدل محلی

[قوانین پروژه](PROJECT_RULES.md) · [هدف‌ها](GOALS.md) · [English README](README.md)

`agent-bridge` یک هستهٔ محلی برای ترجمهٔ قابل‌بازبینی، اتصال عامل‌های CLI مستقل و مسیردهی به مدل محلی یا آنلاینِ انتخاب‌شده است. مسیر آنلاین فقط با انتخاب کاربر فعال می‌شود؛ runtime و تاریخچه در `./.data/` می‌مانند.

## قابلیت‌ها

- ترجمه‌ی مسیر درخواست از فارسی به انگلیسی، همراه با حفظ بلوک‌های کد و قالب Markdown.
- آینه‌ی زندهٔ درخواست‌ها و پاسخ‌های عامل‌های ترمینالی؛ هر اجرای PTY کانال و تاریخچهٔ مستقل دارد.
- کنسول مسیر و گزارش درخواست‌ها؛ مقصد، زمان، نتیجه و مترجم فقط در حد دادهٔ runtime ثبت‌شده نمایش داده می‌شوند.
- ارسال متن از UI به ترمینال واقعی عامل: wrapper پیام را تایپ می‌کند و Enter می‌زند؛ نیازی به پنجرهٔ گفت‌وگوی جدا برای هر CLI نیست.
- چت مستقیم داخلی به‌عنوان میز آزمایش مدل و ترجمه؛ بدون دسترسی سیستمی یا فایل‌خوانی، جدا از آینهٔ ترمینال.
- ثبت آمار توکن، نرخ کش KV، سرعت prompt/decode، و هزینه‌ی فرضی بر اساس چند پروفایل قیمت.
- تنظیمات مترجم آنلاین یا API آفلاین دلخواه با URL و پورت انتخابی کاربر.
- داده‌ها و تنظیمات runtime فقط در مسیر محلی `./.data/` ذخیره می‌شوند.

## نقشهٔ کد و آزمون‌ها

برای اینکه محل هر قابلیت و فایل مسئولش روشن باشد، به [نقشهٔ ماژول‌ها](docs/module-map-fa.md) مراجعه کن. آزمون‌های رگرسیون را با این دستور اجرا کن:

```bash
python3 -m unittest discover -s tests -v
```

## اجرا

ابتدا `llama-server` را روی loopback اجرا کن؛ نمونه‌ی رایج در NixOS:

```fish
ai-serve ~/models/minicpm5-2b-heretic-q5_k_m.gguf \
  -fa on -ctk q8_0 -ctv q4_0 -c 98304 -ub 256 \
  --temp 0.6 --top-p 0.95
```

سپس در ترمینال دیگری:

```fish
cd ~/agent-bridge
python3 bridge.py --host 127.0.0.1 --port 18080 --upstream http://127.0.0.1:8080
```

مرورگر: `http://127.0.0.1:18080/`

## اجرای چند عامل و Mirror ترمینال

هر عامل را در پوشهٔ پروژهٔ موردنظر با wrapper اجرا کن. نمونه‌ها:

```fish
cd ~/agent-bridge
python3 cli.py --wrap pi
# در ترمینال دیگری، همان فرمان را دوباره بزن؛ کانال خودکار pi-2 می‌شود.
python3 cli.py --wrap pi

python3 cli.py --wrap omp
python3 cli.py --wrap hermes
python3 cli.py --wrap codewhale
```

هر اجرای تازه کانال و تاریخچهٔ جدا می‌گیرد؛ نام‌گذاری دستی لازم نیست. اگر خواستی، `--name نام-دلخواه` همچنان برای override وجود دارد. در CLIهایی که adapter خودکار دارند، درخواست مدل به مدل انتخاب‌شده در Bridge می‌رود. عامل‌های دیگر هم می‌توانند از wrapper استفاده کنند، به شرط اینکه تنظیمشان OpenAI-compatible باشد یا endpoint را با تنظیم بومی خودشان به Bridge وصل کنی.

پیامی که از UI می‌فرستی، به PTY همان ترمینال می‌رسد، در TUI تایپ می‌شود و با Enter ارسال می‌شود. `Ctrl+C` اول به عامل می‌رسد؛ برای خروج اجباری از همان wrapper، بار دوم را ظرف حدود ۱٫۴ ثانیه بزن. این کار فقط فرایند همان عامل را می‌بندد؛ سرور Bridge جداگانه روشن می‌ماند.

## مترجم آفلاین دلخواه

در Settings می‌توان Online یا Custom Offline را انتخاب کرد. حالت OpenAI-compatible از `POST /v1/chat/completions` استفاده می‌کند. حالت REST از این قرارداد بهره می‌برد:

درخواست:

```json
{"text":"Text to translate","from":"en","to":"fa"}
```

پاسخ:

```json
{"translation":"ترجمه"}
```

URL و پورت را خود کاربر تعیین می‌کند؛ موتور خاصی به‌اجبار نصب یا اجرا نمی‌شود.

## امنیت و دامنه

- سرور مدل را روی `127.0.0.1` نگه دار و پورت آن را بدون حفاظت روی اینترنت منتشر نکن.
- چت داخلی به فایل‌ها یا shell سیستم دسترسی ندارد؛ عامل‌های CLI فقط از مسیر PTY مستقل خودشان کار می‌کنند.
- جست‌وجوی وب و ارسال فایل به مدل، در صورت فعال‌شدن، باید opt-in و با مقصد روشن باشد.
- Bridge یک مترجم/پراکسی و میز آزمایش مدل است؛ نباید با عامل مستقل کدنویسی اشتباه گرفته شود.
